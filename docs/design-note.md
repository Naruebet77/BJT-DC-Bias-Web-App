# Design Note — BJT DC Bias Web App

## เป้าหมาย

เว็บแอปที่คำนวณ DC operating point ของ BJT Common-Emitter แบบ Voltage-Divider Bias
โดยให้ Python เป็นผู้คำนวณจริง ไม่ใช่ตัวเลขที่ฝังใน HTML

## โครงสร้างและเหตุผล

| ไฟล์ | เหตุผลที่แยกออกมา |
|---|---|
| `dc_bias.py` | สมการวิศวกรรมล้วน ไม่ import Flask จึงเทสต์ได้โดยไม่ต้องมี HTTP และนำไปใช้ซ้ำกับงาน Lab ถัดไปได้ |
| `app.py` | รับผิดชอบ HTTP เท่านั้น: parse ฟอร์ม, เรียก `compute_dc_bias`, จัดรูปแบบตัวเลข, render |
| `templates/index.html` | แสดงผลด้วย Jinja ไม่มีสมการฟิสิกส์ ถ้าสมการเปลี่ยนไม่ต้องแก้ HTML |
| `static/style.css` | แยกหน้าตาออกจากโครงสร้าง |
| `tests/` | แยกเทสต์สมการ (`test_dc_bias.py`) และเทสต์ HTTP (`test_web.py`) |

ผลคือถ้าแก้สมการใน `dc_bias.py` หน้าเว็บไม่ต้องแก้เลย ตราบใดที่ interface ของผลลัพธ์คงเดิม

## การตัดสินใจสำคัญ

**1. อินพุตตัวต้านทานเป็น Ω**
ตารางข้อมูลเข้าในเอกสาร Lab ระบุ `R1/R2/RC/RE [Ω]` จึงรับเป็นโอห์มตรง ๆ และแสดง
ค่าเทียบเป็น kΩ ต่อท้าย (เช่น `100000 Ω (100 kΩ)`) เพื่อให้เห็นว่ามีการแปลงหน่วย
และตรวจค่าที่กรอกได้ง่าย ไม่รับ suffix อย่าง `100k` เพราะจะทำให้ parsing ซับซ้อน
และกำกวมว่าผู้ใช้หมายถึงหน่วยใด

**2. ไม่ clamp ค่า VCE ใน Saturation**
เมื่อ VCE ≤ 0.2 V แบบจำลอง Forward-Active ใช้ไม่ได้แล้ว การ clamp เป็น 0.2 V
เท่ากับการเปลี่ยนไปใช้แบบจำลองอิ่มตัวซึ่งอยู่นอกขอบเขตของ Lab นี้
เราจึงรายงานค่าที่สมการให้มา (อาจติดลบ) พร้อม warning ชัดเจน ตัวเลขติดลบเป็น
สัญญาณให้ผู้ใช้รู้ว่าค่าที่เห็นไม่ควรนำไปใช้

**3. Cutoff ปรับกระแสเป็นศูนย์**
ตรงกันข้ามกับ Saturation: ที่ VTH ≤ VBE รอยต่อ B-E ไม่ forward bias กระแสจริงเป็นศูนย์
การปรับ IB = IC = IE = 0 จึงเป็นขีดจำกัดที่ถูกต้องของแบบจำลอง ไม่ใช่การเปลี่ยนแบบจำลอง

**4. Validation อยู่ที่ `dc_bias.py` ไม่ใช่ `app.py`**
เงื่อนไข R ≤ 0, β ≤ 0, VCC ≤ 0 เป็นข้อจำกัดทางวิศวกรรม ไม่ใช่เรื่องของ HTTP
การวางไว้ในโมดูลทำให้ผู้เรียกทุกราย (เว็บ, CLI, เทสต์) ได้เงื่อนไขเดียวกัน

**5. แสดงป้าย region เสมอ**
ผู้ใช้ต้องเห็นทันทีว่าผลลัพธ์อยู่ใน Active, Cutoff หรือ Saturation ไม่ใช่เห็นเฉพาะตอนมี warning
เพราะการไม่เตือนไม่ได้แปลว่าค่าใช้ได้
