# Reflection — BJT DC Bias Web App

## สิ่งที่ได้เรียนรู้

**1. การเปิดไฟล์ HTML ไม่เท่ากับการรันเว็บแอป**
`templates/index.html` เป็นเพียงแม่แบบที่ Flask นำไป render ถ้าเปิดด้วย `file://`
จะเห็นฟอร์มแต่กด Calculate แล้วไม่มีอะไรเกิดขึ้น เพราะไม่มีใครรับ HTTP request
และไม่มี Python คำนวณ ต้องรันผ่าน `http://127.0.0.1:5000/` เท่านั้น

**2. เส้นทางของข้อมูลจากฟอร์มถึงผลลัพธ์**
ฟอร์มส่งชื่อ–ค่าเป็น `application/x-www-form-urlencoded` → Flask แปลงเป็น `request.form`
→ `parse_form` แปลงเป็น float → `compute_dc_bias` คำนวณ → `format_result` ใส่หน่วย
→ Jinja แสดงผล การแยกขั้นตอนแบบนี้ทำให้รู้ว่าเมื่อผลผิด ควรไปตรวจที่ขั้นตอนไหน

**3. แก้สมการไม่ต้องแก้ HTML**
เมื่อแก้สมการใน `dc_bias.py` หน้าเว็บยังใช้ได้ทันทีเพราะเทมเพลตไม่รู้จักสมการ
มีเพียง interface ของผลลัพธ์เท่านั้นที่ต้องคงเดิม

**4. เหตุใดต้องมี warning เมื่อออกนอก Active Region**
สมการที่ใช้เป็นแบบจำลอง Forward-Active ซึ่งสมมติว่ากระแสสะสมเป็นสัดส่วนกับกระแสฐาน
เมื่อวงจรอิ่มตัวหรือ cutoff สมมติฐานนี้ไม่จริงอีกต่อไป ตัวเลขที่ได้จึงไม่มีความหมาย
ถ้าไม่เตือน ผู้ใช้อาจนำค่า VCE ติดลบไปออกแบบต่อโดยเข้าใจผิด

## ปัญหาที่พบและวิธีแก้

| ปัญหา | วิธีแก้ |
|---|---|
| ค่า VTH ≤ VBE ทำให้ IB ติดลบ | clamp กระแสเป็นศูนย์และแจ้งว่าเป็น Cutoff |
| ค่า VCE ติดลบใน Saturation | ไม่ clamp แต่แสดง warning ว่าค่าใช้ไม่ได้ |
| `100k`, `1,000` ทำให้ `float()` ผิดพลาด | ตรวจและแจ้ง error ภาษาไทย ไม่ให้หน้าเว็บล่ม |
| คำว่า "Active" ไปตรงกับ "Forward-Active" ในเทมเพลต ทำให้เทสต์ผ่านทั้งที่ป้าย region หาย | เปลี่ยนไปตรวจ CSS class `region-active` แทน |
| `url_for('calculate')` ใช้ไม่ได้ก่อนที่ route จะถูกสร้าง | ใช้ `action="/calculate"` ตรง ๆ ในขั้นแรก |

## ข้อจำกัด

- β และ VBE คงที่ ไม่ขึ้นกับกระแสหรืออุณหภูมิ
- ไม่มี DC load line, ไม่มีการคำนวณกำลัง, ไม่ใช่ SPICE
- ไม่มีการรับหน่วย kΩ โดยตรง ผู้ใช้ต้องกรอกเป็นโอห์ม
